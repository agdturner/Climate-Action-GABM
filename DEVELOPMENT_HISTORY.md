## Development Timeline
- [2026-07-10] v0.9 — Degree/centrality-proportional peer fan-out (`k_i ∝ network measure`). Peer chat (the `C` phase) was a flat *send* fan-out: every citizen relayed its reflection to the same `k = min(k_peers, degree)` randomly-chosen neighbours, so a 40-degree hub spread its shifted view no wider than a leaf with two ties — exactly the mechanism limitation the paper's targeting null calls out ("a targeted hub cannot pass its shifted opinion to more neighbours than anyone else … a degree-proportional relay rule … [is] the natural re-test"). New `SurveyedNation._compute_peer_fanout()` in [src/cag/abm/environment.py](src/cag/abm/environment.py) computes a per-citizen fan-out `k_i` scaled by a peer-graph measure — `degree` or `betweenness` (reusing the centrality machinery already built for reach targeting) — under two budget policies: `additive` (the default) sets `k_i = scale·measure_i` so the well-connected simply relay to more people and total relay volume grows with connectivity (the realistic posting-network reading), while `preserve` instead redistributes a fixed total budget so the *mean* fan-out stays `k_peers` (isolating placement from volume, so it stays comparable to the iso-impression result). All non-constant modes clip `k_i` into `[kmin, kmax]` (kmax caps runaway fan-out on high-degree hubs) and never exceed a node's own degree; the map depends only on the static peer graph, so it is memoised per parameter set. `mode="constant"` (the default) reproduces the historical rule byte-for-byte, so existing runs are unchanged. Wired through `run_peer_messaging` / `run_package_peer_messaging`, three exposed `SIM_CONFIG` keys (`peer_fanout_mode` / `_budget` / `_kmax`; budget defaults to `additive` and `kmax` to `10`, with `scale`=1.0 and `kmin`=1 baked as internal defaults) plus the `rt` runtime dict and both `C`-phase dispatch sites in [src/cag/abm/sim.py](src/cag/abm/sim.py), and `--peer-fanout-mode/-budget/-kmax` CLI flags in [src/cag/__main__.py](src/cag/__main__.py). `TestPeerFanout` (13): constant-mode regression, degree hub > leaf, `preserve` mean-preservation on a regular graph, `additive` volume growth, kmin/kmax clamps, never-exceeds-degree, betweenness-requires-network, invalid mode/budget raise, memoisation, end-to-end run, and `k_peers=0` no-op in every mode. Full suite green (680 passed, 1 skipped). Infrastructure only — the actual hub-targeting re-run is deferred; social-scientist docs added to [docs/Simulation_Configuration_Guide.md](documentation/guides/Simulation_Configuration_Guide.md) and the flag reference in [documentation/guides/AIRE_Quickstart.md](documentation/guides/AIRE_Quickstart.md).
- [2026-07-05] v0.9 — Per-side reach targeting: persuadable + network-centrality. The reach lever (`reach_a`/`reach_b`, the audience *fraction* a broadcast reaches) previously always subsampled that audience uniformly at random. `SurveyedNation.apply_reach_subsample` in [src/cag/abm/environment.py](src/cag/abm/environment.py) now takes per-side `targeting_a` / `targeting_b` ∈ `{"random", "persuadable", "degree", "betweenness"}`, modelling *microtargeting* — spending a limited reach budget on the audience members most worth reaching rather than a random slice. `persuadable` keeps the most *undecided* (smallest `|get_real_package_index()|`, i.e. closest to the neutral midpoint); `degree` / `betweenness` keep the most *central* on the peer graph (the hubs / brokers who best amplify a message through peer messaging). All non-random modes hard-rank and keep the top `floor(reach·n)`, with a seeded permutation (same seed as the random arm) breaking ties so the arms differ only by criterion, and all are a no-op at `reach=1.0`. Centrality is a property of the peer graph, so `run_simulation` setup in [src/cag/abm/sim.py](src/cag/abm/sim.py) was reordered to build (and repair) the network *before* the reach subsample; the `random`/`persuadable` arms and the shared `sim_step` counter are provably unaffected (full suite green through the reorder). New `SIM_CONFIG` keys `reach_targeting_a`/`reach_targeting_b` (default `"random"`), `--reach-targeting-a/-b` CLI flags, both hard resume keys. `TestReachTargeting` (10) + `TestReachTargetingCLI` (2). Verified on gpt-5-mini (NB 42): persuadable kept mean |GT| 0.89 vs 2.04, degree kept mean degree 9.17 vs 3.67 — the two modes demonstrably pick different audiences.

- [2026-07-03] v0.9 — Tier-P persona-null ablation (algorithmic-fidelity manipulation check). Can we prove the model actually conditions on each agent's assigned persona, rather than answering from a generic pro-climate prior? New `SurveyedNation.apply_persona_mode(mode, seed)` in [src/cag/abm/environment.py](src/cag/abm/environment.py) rewrites every active citizen's persona under one of three arms — `"real"` (no-op, bit-for-bit identical to prior canon), `"shuffled"` (each agent is given *another* agent's whole persona verbatim via a derangement, so no agent keeps its own but every persona is still a coherent real UK person), and `"neutral"` (every persona replaced by the generic `NEUTRAL_PERSONA_TEXT = "I am an adult living in the United Kingdom."`). Ground truth is **never** touched — real opinions are always read from `original_survey_data`, so the scoring target is identical across all three arms and accuracy differences isolate persona-conditioning. Personas are snapshotted *before* any override is written so the shuffle copies originals, not already-overridden strings. Mechanism in [src/cag/abm/agent.py](src/cag/abm/agent.py): new `SurveyedCitizen.persona_override` attribute + `get_persona()` hook that returns the override when set. Wiring in [src/cag/abm/sim.py](src/cag/abm/sim.py): new `SIM_CONFIG["persona_mode"] = "real"` (34 keys total), `VALID_PERSONA_MODES = ("real", "shuffled", "neutral")`, validated in `_resolve_runtime`, applied in `run_simulation` alongside the other audience manipulations (reach / audience-cap) so it runs on both fresh and resume paths; the returned map is stored as `nation.persona_map`. Audit trail: new `persona_map.csv` (`agent_id, source_agent_id, persona_mode`) via `_RESULT_CSV_SCHEMAS["persona_map"]` in [src/cag/io/results.py](src/cag/io/results.py) (final-output only, in `_CHECKPOINT_SKIP_KEYS`). `persona_mode` added to `_RESUME_HARD_KEYS` in [src/cag/io/checkpoint.py](src/cag/io/checkpoint.py) (changing the arm mid-run would invalidate the comparison). - [2026-07-03] v0.9 — Broadcast-frequency-asymmetry CLI. The per-day `make_phases` shorthand (v0.5 §19) could already make one side broadcast more often than the other, but only by hand-writing a `days` list. Three new flags in [src/cag/__main__.py](src/cag/__main__.py) apply the same asymmetry to *every* day when `--days` is a plain integer: `--broadcasts-a N` / `--broadcasts-b M` (default 1/1) set each politician's daily broadcast count, and `--interleave` / `--no-interleave` (default on) chooses between alternating (`A,B,A,…`) and block (`A,A,…,B`) ordering. New `build_days(n_days, broadcasts_a=1, broadcasts_b=1, interleave=True)` loops the days through `make_phases(..., a_first=(i % 2 == 0))` so the alternation-of-first-speaker convention is preserved; `build_config` pops the three knobs from the merged dict, expands an integer `days`, and warns if they are set while `days` is already an explicit list (in which case they are ignored). Peer chat (`C`) is always appended — disable with `--k-peers 0`. The default 1-vs-1 reproduces the classic schedule exactly. This is a **frequency** lever (how *often* a side speaks), orthogonal to `reach_a`/`reach_b` (what *fraction of the audience* a single broadcast reaches). New `TestBroadcastFrequency` class in [tests/test_cli.py](tests/test_cli.py) (9 tests: symmetric-default unchanged, block vs interleave expansion, knob-popping, flag parsing, absent-when-unset, dry-run). Documented in [docs/Simulation_Configuration_Guide.md](documentation/guides/Simulation_Configuration_Guide.md) ("Broadcast-frequency asymmetry from the command line") and [docs/Model_Design.md](documentation/research/Model_Design.md) §32.
